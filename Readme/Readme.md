## Замечания, которые намеренно не приводили к изменению поведения

- **`popup.html` — `lang="ru"`.** Оставлен как fallback до загрузки сохранённого языка. `applyTranslations()` устанавливает фактический `document.documentElement.lang` после загрузки предпочтений.
- **`author` в manifest.** Не добавлен: авторство следует указывать в карточке магазина расширений; добавление необязательного поля в манифест не устраняет дефект кода.
- **Однократная глобальная очистка старого индикатора.** Не добавлялся флаг `captureCircleCleaned`. Popup очищает текущую активную вкладку при открытии; глобальный флаг мог бы пометить очистку завершённой после неудачной попытки на `edge://` или до посещения остальных открытых вкладок. Это безопаснее, чем одноразовая очистка, которая пропустит другие вкладки.
- **Ожидаемые `catch` без лога.** Сохранены там, где ошибка ожидаема при закрытии popup, уже недействующем контексте, отсутствии обработчика на неподдерживаемой странице либо при откате/сериализации операций хранения. Диагностические логи добавлены к ошибкам, полезным для поиска проблем применения настроек и обмена сообщениями.
- **Схема резервной копии.** `schemaVersion` намеренно не повышалась: новых обязательных полей не добавлено, а устаревший ключ удаляется совместимо.

- Обычные ошибки JavaScript не проглатываются: повторно выбрасываются ошибки, которые не относятся к уничтоженному extension context.

## Исходный архив

## Исходный архив

- Архив читается, ошибок целостности ZIP не обнаружено.
- В архиве была стандартная структура расширения Chrome Manifest V3: `manifest.json`, service worker, popup, content script, offscreen-документ и иконки.
- Все JavaScript-файлы исходной версии проходят синтаксическую проверку Node.js; исходная ошибка была логической, а не синтаксической.

## Найденная первопричина

Popup отправлял `chrome.runtime.sendMessage({ type: 'START_CAPTURE', tabId })` без `streamId`. Такое сообщение доставлялось также в `offscreen.js`, чей обработчик принимал любой `START_CAPTURE` и передавал `undefined` в `getUserMedia()` как `chromeMediaSourceId`. В то же время service worker отдельно получал ID и отправлял второй `START_CAPTURE`, из-за чего два запуска могли пересекаться.

## Что исправлено

1. Offscreen-документ обрабатывает только сообщения с `target: 'offscreen'`; запрос popup без этого поля игнорируется.
2. Service worker ожидает ответ от offscreen-документа и отмечает вкладку активной только после подтверждённого успешного захвата.
3. Запуски сериализованы, старый медиапоток останавливается до нового захвата, а `streamId` используется сразу после получения.
4. В журнал и интерфейс popup выводится имя и текст исходной ошибки вместо бесполезного `[object DOMException]`.
5. Добавлены очистка после неудачного старта, обработка остановки захвата и отображение ошибок в интерфейсе.
6. В `manifest.json` установлена минимальная версия Chrome 116 — версия, с которой ID из service worker можно использовать в offscreen-документе.

## Проверки

- `node --check` для всех JS-файлов — пройдено.
- Проверка JSON `manifest.json` — пройдена.
- Проверка локальных ссылок JS/CSS и DOM-ID в popup — пройдена.
- Тест offscreen-маршрутизации: широковещательный `START_CAPTURE` без target игнорируется; адресованный запуск подтверждается; `STOP_CAPTURE` останавливает медиадорожку — пройдено.
- `unzip -t` итогового архива — пройдено.

Полный запуск с реальным воспроизведением звука в браузере в этой среде не удалось завершить: headless Chromium завис при старте. Поэтому финальная проверка звука должна быть выполнена в установленном Chrome после загрузки исправленного расширения.

# Volume Controller Pro 4.3.0 — Bass Boost update and audit

## Что добавлено
- Отдельный переключатель Bass Boost.
- Регулировка усиления низких частот от 0 до +12 dB.
- Значение по умолчанию: Bass Boost включён на +6 dB — умеренная настройка для обычных наушников и небольших колонок.
- Low-shelf EQ на 105 Hz: подчёркивает басовую область, практически не поднимая средние и высокие частоты.
- High-pass на 25 Hz для снижения субсонического гула.
- Настройки Bass Boost сохраняются в `chrome.storage.local` и передаются в offscreen audio graph.
- Добавлены двухступенчатая компрессия и быстрый ограничитель пиков для снижения риска слышимого клиппинга при высоком усилении.
- Reset возвращает громкость к 100%, снимает mute и включает Bass Boost на +6 dB.
- Версия расширения обновлена до 4.3.0.

## Аудиоцепочка
`Tab stream → high-pass 25 Hz → low-shelf 105 Hz → volume gain → compressor → peak limiter → audio output`

Web Audio API `BiquadFilterNode` типа `lowshelf` добавляет/уменьшает децибелы ниже заданной частоты; усиление регулируется `gain` в dB. Параметры компрессии настраиваются через стандартный `DynamicsCompressorNode`.

## Результаты проверок
- JavaScript-синтаксис: все JS-файлы проходят `node --check`.
- `manifest.json`: корректный JSON; версия 4.3.0.
- Элементы Bass Boost и другие DOM ID, используемые в `popup.js`: присутствуют.
- Мок-тест `offscreen.js`: успешный захват тестового аудиопотока, построение аудиоцепочки и применение изменения уровня Bass Boost.
- Архив проверен через `unzip -t`.

## Важное ограничение
Мок-тест не заменяет прослушивание в реальном Chrome. Из-за особенностей аппаратуры/наушников субъективно лучшая громкость баса различается. Для начала рекомендуется +4–6 dB; +9–12 dB может давать гул, искажения или срабатывать ограничитель чаще, особенно при общей громкости выше 100%.




# Volume Controller Pro 4.4.0 — аудит Voice Boost

## Что добавлено
- Отдельный переключатель Voice Boost в popup.
- Регулятор усиления речи от 0 до +8 dB; исходное значение — +3 dB.
- Два плавных EQ-фильтра: мягкая поддержка области 1,25 кГц (35% установленного значения) и основная зона разборчивости около 2,8 кГц.

- Кнопка сброса возвращает Voice Boost к включённому состоянию +3 dB.
- Popup может прокручиваться вертикально, чтобы новые настройки не обрезались.
- Версия Manifest V3 обновлена до 4.4.0.

## Почему такие значения
+3 dB — умеренная отправная точка для подчёркивания разборчивости. EQ применяется ко всему аудио вкладки и усиливает диапазоны, в которых часто присутствуют речевые согласные и разборчивость; это не AI-изоляция голоса и не выделение вокала из музыки. Разным наушникам, колонкам и записям могут требоваться другие значения.

# Volume Controller Pro 4.7.0 — баланс и оптимизация

## Цель
Настроить поведение по принципу «золотой середины»: приятный бас и разборчивая речь без чрезмерной окраски звука, а также снизить нагрузку от визуализатора и спектрограммы.

## Сбалансированный аудиопрофиль
- Общая громкость при сбросе: 100% (без принудительного усиления).
- Bass Boost по умолчанию: включён, +4 dB, фильтр low-shelf на 105 Hz.
- Voice Boost по умолчанию: включён, +2 dB; мягкая полоса нижней середины 1.25 kHz (35% от заданного уровня) и полоса разборчивости 2.8 kHz.
- High-pass на 25 Hz для уменьшения инфранизкого гула.
- Компрессор: threshold −18 dB, knee 18 dB, ratio 2.6:1, attack 10 ms, release 250 ms. Это мягче старого профиля и уменьшает ощущение чрезмерного «пампинга».
- Финальный ограничитель оставлен для контроля пиков: threshold −1.5 dB, ratio 20:1, attack 3 ms, release 120 ms.
- Диапазоны регулировки не урезаны: громкость 0–600%, Bass Boost 0–12 dB, Voice Boost 0–8 dB.

## Сохранение настроек
Добавлена одноразовая миграция профиля. Если в сохранённых настройках стоят прежние заводские значения Bass +6 dB и Voice +3 dB (или значения ещё не были сохранены), они заменяются на сбалансированные +4 dB / +2 dB. Необычные/пользовательские значения EQ сохраняются. При повторном открытии popup сохранённые значения повторно применяются к уже работающему offscreen audio graph.

## Оптимизация визуализатора
- Отрисовка спектра ограничена примерно 30 FPS; при системном `prefers-reduced-motion` — примерно 15 FPS.

# Аудит безопасности и качества — Volume Controller Pro 4.7.15 (Microsoft Edge)

Дата аудита: 22 октября 2026 г.

## Итог

Это статический аудит и локальные тесты, а не независимый penetration test.

## Срочные проблемы

**Не выявлены в пределах проверенного исходного кода.** Это не означает гарантированного отсутствия неизвестных уязвимостей.

## Средние проблемы — исправлены

1. **Избыточный постоянный доступ ко всем сайтам.** Раньше manifest запрашивал `host_permissions: <all_urls>` и внедрял `content.js` на всех сайтах. Оба механизма удалены. Индикатор громкости теперь внедряется в текущую вкладку при открытии popup через `activeTab` и `scripting`. Это сокращает область доступа: расширение больше не запускает свой content script на каждой посещённой странице.
2. **Недостаточная проверка отправителя команд.** Background теперь принимает управляющие команды только от URL собственного `popup.html`. Offscreen и content script дополнительно проверяют, что команда пришла из контекста расширения background, а popup принимает данные спектра только от `offscreen.html`.
3. **Недостаточная проверка параметров аудио-команд.** Добавлены строгие проверки типа и диапазона громкости (0–6), mute, Bass Boost (0–12 dB), Voice Boost (0–8 dB), идентификатора вкладки, флага визуализатора и текста badge. Команды аудио применяются только к вкладке, для которой расширение запустило захват, и к текущей активной вкладке.
4. **Гонка при начальной загрузке.** Настройки аудио теперь читаются до запуска захвата, а аудиоконтролы отключены до завершения инициализации. Изменения громкости сериализованы относительно переходов захвата, чтобы начальный запрос не перезаписывал действия пользователя.

## Низкие проблемы и оптимизация — исправлены

1. **DOM injection sink.** Удалено использование `innerHTML` для отображения процента громкости; значение вставляется через текстовый узел.
2. **Лишняя работа на страницах.** Удалён постоянный `MutationObserver`; индикатор создаётся по необходимости и не создаётся на странице только из-за загрузки content script.
3. **Избыточное разрешение `tabs`.** Удалено; расширение использует `activeTab`, `scripting` и только необходимые сведения о текущей вкладке.
4. **Повторная вставка CSS.** Перед вставкой стилей проверяется, есть ли content script в изолированном мире вкладки.

## Импорт конфигурации `.cfg`

# Глубокая проверка Volume Controller Pro 4.7.39

**Пакет:** Microsoft Edge / Chromium, Manifest V3  
**Результат:** доступные статические и изолированные тесты пройдены. Реальное воспроизведение/захват звука в установленном Edge в этой среде не выполнялось.

## Что изменено

### Аудиоцепочка
Порядок обработки изменён на:

`High-pass → Bass EQ → Voice EQ → EQ headroom → compressor → master gain → night-mode makeup → analyser → limiter (если включён) → output`

Это отделяет поведение компрессора от положения основного ползунка громкости. Ограничитель остаётся последним защитным узлом, а анализатор измеряет уровень после регулятора громкости перед ограничителем. При отключённом ограничителе анализатор направляет сигнал непосредственно на выход, не создавая дублирующего аудиопути.

### Ресурсы и устойчивость
- После остановки захвата отключаются узлы и медиатрек, затем `AudioContext` приостанавливается. Следующий запуск дожидается окончания приостановки и повторно возобновляет контекст.
- Все управляющие элементы настроек, которые зависят от первичной загрузки настроек, блокируются до её завершения. Это предотвращает сохранение начальных значений поверх реально сохранённых параметров.
- Записи через `chrome.storage.local.set` в popup выполняются через последовательную очередь, чтобы не перекрывать друг друга при быстрых последовательных изменениях.
- Спектрограмма повторно использует пиксельный буфер и предварительно рассчитанные горизонтальные индексы; они перестраиваются только при смене размера Canvas или количества полос.
- Политика CSP для страниц расширения усилена до `object-src 'none'`.

## Результаты по категориям

### Экстренные / критические
Подтверждённых критических проблем в выполненных проверках не обнаружено. Это не заменяет независимый penetration test или тестирование в установленном Edge.

## 2. Найденные дефекты и исправления

### Средний — состояние захвата терялось после перезапуска service worker

В Manifest V3 фоновый service worker может завершаться после простоя; его глобальные переменные при этом теряются. Если offscreen-документ продолжал держать аудиопоток, фон мог потерять `currentCapturedTabId`, из-за чего повторное открытие popup могло ненужно перезапустить поток, а обновление громкости — отклоняться. Это поведение согласуется с документированным жизненным циклом MV3 service worker: глобальное состояние не является постоянным хранилищем. См. официальную документацию Chrome: https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle

**Исправлено:** добавлена синхронизация состояния с существующим offscreen-документом через `GET_CAPTURE_STATUS`. При повторном открытии popup уже активный поток той же вкладки переиспользуется, а актуальное состояние проверяется до применения громкости.

### Низкий — аудиодорожка могла завершиться вне контроля расширения

**Исправлено:** обработчик события `ended` останавливает поток, отключает узлы аудиографа, очищает таймеры и сбрасывает состояние захвата.

### Низкий — детектор пиков проверял сигнал слишком редко

Фиксированный опрос раз в 100 мс мог пропустить короткий переходный пик между чтениями.

**Исправлено:** частота опроса рассчитывается исходя из размера окна анализатора и sample rate; окна частично перекрываются, интервал ограничен диапазоном 10–100 мс. При 48 кГц и FFT 2048 интервал составляет около 32 мс. Это улучшает вероятность обнаружения кратких пиков, но не гарантирует абсолютное отсутствие искажений.

- **Средние:** выявлен вероятный race condition между остановкой старого потока и запуском нового при быстрых переключениях вкладок или закрытии вкладки во время захвата. Требует исправления и проверки в браузере.

## Средний приоритет — возможная гонка остановки и старта захвата

Обработчики `chrome.tabs.onRemoved` и `chrome.tabCapture.onStatusChanged` в `background.js` напрямую отправляют `STOP_CAPTURE` в offscreen-документ. При этом команды `START_CAPTURE` / `STOP_CAPTURE` от popup и обработчик `tabs.onUpdated` проходят через `captureQueue`. Событийная очистка таким образом находится вне общей очереди.

При редком совпадении событий остановка старого потока может отправиться одновременно с запуском нового. Если старый `STOP_CAPTURE` обработается после нового `START_CAPTURE`, новый поток может остановиться, а UI на короткое время может показать устаревшее состояние. Это **вывод по коду, а не воспроизведённый в браузере дефект**.

**Рекомендация:** проводить очистку после закрытия вкладки и завершения трека через общий сериализованный механизм; перед остановкой проверять, что ID активного потока по-прежнему совпадает с ID вкладки из события. Событие для старого потока не должно иметь право останавливать более новый поток.

## Низкий приоритет — резервный номер версии

В `popup.html` резервный текст версии всё ещё равен `4.7.42`, а версия в `manifest.json` — `4.7.44`. Нормально работающий `popup.js` заменяет значение на версию из манифеста, поэтому это не мешает обычной работе, но при отказе скрипта HTML показывает устаревшую версию.

**Рекомендация:** обновлять fallback-значение в HTML при каждом релизе либо заменить его нейтральным текстом, который всегда инициализируется из манифеста.

## Низкий приоритет — остатки индикатора после выключения

`disableCapture()` прекращает аудиозахват и визуализацию. При этом внедрённые ранее `content.js` и `styles.css` не удаляются со страницы до навигации/перезагрузки; индикатор сам скрывается по таймеру, а content script остаётся слушателем сообщений. По текущему коду это не продолжает захват аудио, но оставляет вспомогательный код в документе.

**Рекомендация:** при необходимости добавить явное сообщение очистки индикатора; учитывать, что повторное включение не должно создавать второй обработчик или дублирующий CSS.
